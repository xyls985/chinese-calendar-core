# 测试与核验记录

本项目区分两个问题：计算是否符合独立资料，以及代码重构是否改变既有结果。共享回归样例只回答后者，不能替代权威历表或星历比较。

## 外部核验（2026-10-04）

| 来源与内容 | 覆盖 | 结论 |
|---|---:|---|
| 香港天文台 1901–2100 年逐日历表 | 200 年，73,049 个独立日期，4,800 次节气 | 1929–2100 年的 62,822 天，农历及节气日期全部一致 |
| 香港天文台历史区间 | 1901–1928 | 农历差异 90 天；6 次节气日期不同，涉及 12 个日期行 |
| 四语言互相比较 | 每版 165,257 个时刻 | 输出一致；这不是四套独立天文算法互相证明 |
| sxtwl 2.0.7 逐日辅助对照 | 1813–2100，共 105,190 天 | 日柱全部一致；农历历史差异 240 天 |
| sxtwl 现代四柱边界辅助对照 | 98,726 个时刻 | 日柱、时柱一致；875 个年/月柱边界差异 |
| NASA 1901–2000 年新月表 | 1,237 次新月 | 换算后的 UTC+08:00 日期全部一致；相对表列分钟最大偏差约 71.36 秒 |
| 中央气象署 2026–2027 年初节气 | 28 次 | 12 个显示分钟差 1 分钟；相对表列分钟最大偏差约 61.87 秒 |
| 中央气象署同期合朔 | 14 次 | 相对表列分钟最大偏差约 71.61 秒 |
| 时辰与晚子时 | 完整六十日周期，每小时 00、59 分，共 2,880 个时刻 | 按当日晚子时约定通过 |

样本之间有重叠，不能把数量相加宣称独立覆盖。875 个四柱差异来自刻意密集采样的交节窗口，不是随机日期错误率。sxtwl 是辅助软件实现，不标作官方数据源。

香港天文台历史农历差异区间为：

- 1914-11-17 至 1914-12-16；
- 1916-02-03 至 1916-03-03；
- 1920-11-10 至 1920-12-09。

历史节气差异为 1912 年小雪、1913 年秋分、1917 年大雪、1923 年雨水、1927 年白露、1928 年夏至。历史规则的解释见 [ALGORITHMS.md](ALGORITHMS.md)。

香港天文台明确说明部分远期新月或节气接近午夜，预测误差可能改变日期。这里的“一致”指与核验时已发布的官方表一致，不承诺未来不会修订。1979 年大寒的精确星历与历表日期也存在口径差异，本项目与香港天文台表一致，未将其列为官方日期失败。

## 开源整理后的回归

仓库提供 1,008 条跨整个输入范围的共享样例，包括春节、闰月、2033 年闰十一月、晚子时及已知近似交节边界。四种语言还分别测试：

- 拒绝无效日期、时间和超出 1813–2100 的年份；
- Python / JavaScript 拒绝字符串、布尔值及非整数；
- 结构化结果、默认 12:00、无节气的空值；
- Python、JavaScript 导入不执行演示；
- JavaScript 的 CommonJS、ESM 与命令行入口；
- Java 的数字输出不依赖系统默认 Locale；
- C++ 的公共头文件与独立链接。

执行 `python scripts/test_all.py` 可重跑这些检查。GitHub Actions 还配置了 Python wheel、Java Maven 和 CMake 构建；配置存在不代表远程 CI 已经运行。

本次整理以完整 165,257 个审核时刻检查新旧格式化结果，Python、JavaScript、Java、C++ 四版均为 **0 项差异**。精度已知差异保留在回归样例和算法文档中，不用“测试全部通过”暗示这些限制已修复。

## 复核独立资料

1. 从 [REFERENCES.md](REFERENCES.md) 获取对应年份的官方历表或天文表。
2. 明确资料的时间基准、日期粒度和历史历法口径。
3. 每年核对完整的 365/366 个日期，检查是否有缺失或重复行。
4. 比较农历年、月、日、闰月与节气日期；另外核对交节瞬时。
5. 将输入、实际值、参考值和资料链接附在问题报告中。

本仓库不打包第三方完整历表或本机对照脚本。共享 fixture 是实现的回归输出，不是官方原表。
